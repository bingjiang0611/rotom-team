## Acceptance boundaries

- Type checking and automated tests do not establish real-account authorization, provider approval, complete billing or target-device readiness.
- Native acceptance must cover individual credential routing, history handoff, fork, compaction, app permissions, persistence and safe recovery.
- Unknown inference, tool and refresh outcomes remain unknown. Do not replay them or substitute a zero-cost result.
- Installation, restart, backup, restore and rollback must be verified on the authorized target. Restore excludes refresh grants and does not undo remote side effects.
- Keep account identities, request/session records, SSH addresses, device names and private operational logs outside Git.

See [NATIVE-DELIVERY.md](NATIVE-DELIVERY.md) for R1–R8, [NATIVE-RECOVERY.md](NATIVE-RECOVERY.md) for recovery rules, and [PROVIDER-POLICY.md](PROVIDER-POLICY.md) for provider and distribution constraints.

## Native tree selector

`node --test test/native-tree.test.ts` compares browser row text/order/connectors against the pinned
rotom 0.1.25 `TreeSelectorComponent` for all five filters, search and folding. This is a native-output
comparison, not a snapshot generated by the browser implementation. Removing the tool-only-message
filter makes both checks fail.

`node test/native-commands-proof.ts --ui` additionally checks search, empty results, Escape-to-clear,
arrow selection and Enter-to-navigate through the actual browser, while preserving cancellation,
editable drafts, explicit summary billing and immutable audit history. It captures the tree after its
opening animation at desktop and 390px phone-emulated widths; checks horizontal containment, visible
summary controls, selection after resizing, 44px touch rows and a 16px mobile search field. These are
Chromium checks, not real-device/iOS-keyboard verification.

The reference is the user's terminal Session Tree screenshot and the pinned native selector source:
compact role-colored rows, branch connectors, active-path dots, tool-call summaries rather than raw tool
results, and keyboard navigation. Team's generic full-width button list was not a tree representation.
The port keeps native execution behind Team's existing authorization and receipt path; it is not a PTY
or generic TUI bridge. Personal design-library searches had stale old-machine source paths; no personal
component was imported. Visual acceptance remains pending.

Current limits: default terminal shortcuts only (browser/OS-reserved keys may intercept them; filter
buttons remain available); no label editing or full-entry copy shortcut; message search follows the
native 200-character excerpt rather than full transcript search. Long rows clip to the viewport; native
automatic horizontal panning for deeply nested branches is not ported. If clipping hides the selected
entry's identity in real branched histories, add selected-anchor panning with a deep-tree browser fixture.
All rows are rendered; no large-history virtualization claim is made. Other supported slash dialogs are described below.
TUI-only extensions can be discovered but need an explicit Web adapter or native RPC UI support to work. Recheck
native parity when updating the runtime pin.

## Native command adapters and Goal

```sh
node --test test/rotom-commands.test.ts test/rotom-rpc.test.ts test/team-command-policy.test.ts test/native-goal-form.test.ts
node test/native-commands-proof.ts --ui
node test/rotom-goal-proof.ts
npm run test:kernel:ui
```

These scripts use the actual pinned runtime, isolated member HOMEs, loopback model/OAuth fixtures and Chromium.
`native-commands-proof` writes `native-commands/report.json` and screenshots under its printed temporary data root.
It checks first-session discovery without inference; retained snapshots beyond 30 seconds and after restart without native startup; owner-only shared settings; viewer/other-member catalog privacy; model A→B and later payer/model
requests; fixture native titles and Team rename across handoff; native branch JSONL/HTML export; positive
owner-private reasoning before cross-member clone filtering; earlier SECOND-entry fork/tree with THIRD absent
from the new branch and later inference; request replay/conflicts; native settings and slash compaction with persisted
summary/usage; default extension admission and protected builtin refusal; and `/context` before/after model requests
without inference. Personal Qoder API fixtures assert credential ownership and private result delivery;
they are not real-account billing evidence.

The browser proof chooses native entry IDs, restores fork/tree drafts without submitting them, invokes an authorized
native branch summary and checks persisted usage, preserves a draft on actual native extension cancellation, and checks
custom-message text extraction. HTTP coverage also checks native no-op navigation. Native RPC exposes cancellation but
not its reason; summary-abort reason discrimination is not verified or claimed. Audit transcript records remain visible
while native branch checks exclude the abandoned user entries.

Error fixtures call the trusted executor below HTTP admission; their extra slash names are explicitly rejected over HTTP.
A fixture appends a real native effect and then throws. The command remains `unknown`; restart and same-request retry
add neither inference nor native bytes. The separate Team proof retains known clean-stop continuation and checks
that crashed unknown prompts remain fenced across restarts without another model request. It asserts that native
skill expansion receipts remain `prompt`, not non-recoverable extension handlers.
`test/startup-recovery.test.ts` also covers dead-PID unknown attempts and legacy pending/interrupted plans through
two real app reopen cycles, with zero automatic submissions and unchanged receipt/plan readback.

The browser uses ordinary fixture input hooks to send 20 native status/widget updates and verifies one keyed slot per key,
followed by removal while the handler is still live. Goal waiting controls remain usable without a status-toast pile-up; plain composer input wakes
the same workflow. The low-level Goal proof verifies a real timer wake, Stop with unknown outcome, pause, explicit wake and queued native skill expansion/wake, retaining one receipt/member. These are distinct from merely receiving a command acknowledgement.

The browser also checks completion-only Tab/partial Enter, the personal thinking picker, owner settings cycling,
readable private quota/unknown values, the real browser input dialog with empty Enter cancellation, and Goal manager
start/edit/confirmed-clear. A reserved one-word objective is refused without dispatch. Goal budget validation and literal
quote/newline encoding are compared directly against the pinned native parser, not duplicated expected output.
A same-name template cannot authorize a hidden extension registered by resource reload or during an active prompt:
both paths reject against the actual native registry before handler effects. Rapidly reopening Goal after edit starts a
fresh sheet even before the previous exit animation finishes; it does not retain the old edit form.
Fork begins on the latest native user message and supports arrow/Enter selection. Goal/tree are checked at a 390px
viewport; screenshots wait for finite transitions rather than capturing a partially transparent sheet.

The same proof holds a synthetic model response open: skill submit returns an active prompt receipt, and the browser
clears its draft before inference finishes. Reverting only the early-return change makes the held-skill admission test
time out; restoring it passes. The Team kernel proof waits for the admitted skill's journal receipt to settle before
checking expanded model input, rather than treating admission as completion. Live thinking changes through configure, slash input and the dedicated chip
keep the native startup count, segment, payer/model and historical binding unchanged; the next actual loopback provider
request carries the new reasoning effort. It checks native clamping, other-member/viewer denial, busy mixed-model denial,
unknown-lease refusal and effective level after a server restart/new native process. Chromium checks `off` visibility,
unsent-draft preservation and an unclipped thinking value at 390px. Journal tests separately check ancestry (not abandoned
branch order), initial-binding immutability and restart readback. Transport-loss/Stop races specifically during a thinking
write are not fault-injected; they use the existing unresolved-command fence and no-replay transport.

The visual reference is the supplied bug screenshots and pinned native thinking selector/RPC behavior. The local repair
reuses the existing chip and selector, without a new theme or component library. Phone layout hides only the word
“Thinking”, not its value. Personal library searches found no reusable selector and stale old-machine references.

### Context usage map

`node --test test/native-context.test.ts` compares the browser's 16×16 map (plus two other geometries) directly with
pinned `pi-context-view/src/ui/usage-map.ts` across 138 distributions: empty, tiny, mixed, full and overflowing windows,
and fractional boundaries. It also executes the native number formatters for token/percentage comparisons. A negative
control changes the mixed-cell threshold and verifies that native comparison detects the difference. Buffer/free-space
checks cover a reserve larger than the remaining window; missing/invalid windows stay unknown instead of zero.

`node test/native-commands-proof.ts --ui` checks the actual production context sheet with the native pre-request data
and a synthetic high-occupancy terminal-shaped snapshot. It checks 256 cells, distinct category colors, percentages,
default per-tool breakdown, mouse/Enter/Space expansion, side-by-side desktop and stacked mobile layouts, and containment
at 390px and 320px. It renders unknown and empty windows without another model request. Screenshots include desktop,
phone, light-theme and unknown-window states. Layout checks do not establish physical-device or full accessibility
acceptance. Native theme overrides, Fit zoom and raw-content previews remain outside this browser projection.

No real account, external sharing upload, deployment, physical-device automation, financial reconciliation or arbitrary
third-party extension is accepted by these fixtures. Run the commands on the final artifact; older logs are not evidence
for a later edit.
